このページの使い方

Microsoft 365 Copilot のエージェント（厳密タスク実行／成果物検収）に貼る「受入基準」と「手順」を1か所にまとめたものです。エージェントのナレッジには、このページのURLと「実験手順ページ」のURLを登録してください（公開Webサイトは最大4件・各URL2階層まで）。

  • 受入基準Rタスクごとに本文へ貼る
  • 3エージェント逐語抽出／作成／検収
  • 5段の工程抽出→作成→検収→修正→再検収
  • 部品正規化表・数値突合・DOT・記録欄
公開範囲の注意：大学配布の実験テキスト本文や、それを要約した物性一覧を、この公開ページに転載しないでください。このページにはルール・手順・雛形だけを載せ、原典PDFと物性一覧PDFはタスクごとに添付する（またはナレッジの「埋め込みファイル」として入れる）方式にします。

1. 3エージェントの役割分担

エージェント役割出すものやらないこと
①原典逐語抽出原典の指定範囲を要約せず操作表へ操作表・定義一覧・外部参照一覧・文字化け一覧・抽出漏れの疑い本文（目的・原理）を書くこと
②厳密タスク実行（実験ノート作成）操作表と受入基準Rから本文＋付録A〜Fを組む本文・フローチャート・付録A〜F承認前の作成、出典のない断定
③成果物検収成果物と原典を突合し違反だけを列挙重大度つき指摘表改善提案・総括・書き直し

②で作り、③で壊す。①を省くと操作の抜けが本文に伝播します。

2. 工程（1実験あたり5プロンプト）

段送り先すること次へ渡すもの
段1①逐語抽出操作表一式 → 段2へ貼る
段2②計画提示 → 承認 → 本文＋付録PDF／本文 → 段3へ
段3③検収（指摘のみ）指摘表 → 段4へ
段4②重大度 高・中の修正修正版 → 段5へ
段5③再検収（解消／新規のみ）残件を人間が確認
段2では必ず「承認」と書くまで成果物を作らせません。計画段階で受入基準の不足を出させ、ここで潰します。

4. 受入基準 R（タスクごとに貼る本文）

【受入基準 R】この全項目を満たすこと。付録Aの充足表では1件ずつ判定する。

■S 出典・情報源
S1 原典準拠：添付「2026無機実験テキスト.pdf」の記載に基づく。原典にない操作・数値・反応式を追加しない。
S2 物性の第一出典：「無機実験_物性一覧.pdf」を第一出典とし、値がある項目はその値を採用する。
S3 物性のWeb補完：物性一覧に無い項目は 公的機関 → PubChem → NIST Chemistry WebBook → 試薬メーカー最新版SDS → その他の一次DB の順で補完する。
S4 出典の記載：ファイル参照はファイル名＋掲載ページ＋物質名/項目名。Web参照は情報源名＋ページ名/SDS名＋URL＋公開日/改訂日＋参照日＋対象の形態・濃度・水和状態・純度。
S5 参考文献：使用した全情報源を末尾に列挙する。
S6 出典なき断定の禁止：出典を示せない情報は本文に書かず、付録B（未確認事項一覧）へ回す。一般知識で埋めない。

■C 構成・体裁
C1 構成順：目的 → 原理 → 使用する器具・試薬 → 実験操作。その後に付録A〜F。
C2 目的：1〜2文。
C3 原理：2.1、2.2…の副見出しを付ける。反応式・反応経路・分離原理・測定原理・装置の使い方・背景・終点/終了条件・計算原理を書く。半ページ〜1ページ目安（重要事項が多ければ制限しない）。
C4 器具表：名称／大きさ・規格／個数の3項目。個数が原典に無い場合は必要最低限を括弧付きで示す（例：(1)、(1式)）。推測不能なら空欄。
C5 試薬表：名称／構造式・化学式／性質／出典の4項目。有機化合物は構造式を図または明確な図式で示す。
C6 性質欄：外観・状態・形状（色・状態・形状・臭い・結晶形・粉末/粒状/金属線/金属網・吸湿性・潮解性・風解性・水和状態）→ 分子量または式量 → 融点 → 沸点 → 密度 → 溶解性 → 特徴的な化学的性質 → 危険性 → 実験上の注意 の順。純物質/水溶液/無水物/水和物を区別する。適用できない値は理由を書く。
C7 番号：章・節・項を文書全体で連続かつ階層的に整合させる。原典の操作番号を残す場合は成果物の節番号と区別して併記する（例：4.2 G3の恒量化（原典：1））。
C8 形式：Wordで組版してからPDF化する。化学式の上付き・下付きが正しく表示され、文字化け・欠落・見切れがないことを確認する。
C9 作成順序：Ni重量 → 電解重量分析 → 原子吸光 → ガスクロマトグラフィー → 酸化還元滴定 → 中和滴定 → 沈殿滴定 → フェライト → キレート滴定 → 溶媒抽出吸光光度分析。
C10 定義：原典の「これを○○とする」「○○をTとする」等を全部、定義欄または該当操作の直後に書く。

■O 操作・フローチャート
O1 実験操作は原典の項目ごとにフローチャートで示す。
O2 視認性：操作内容を損なわない範囲で文章を短くし、二次元的に配置する。同時並行・分岐・合流は線と矢印で示す。
O3 表記規則：開始・終了端子、条件分岐、反復、入出力を守る。
O4 フローチャートは表形式でなく図として示す。
O5 短文化で省略される注意事項は、対応する操作の直下または直近に書く。
O6 各操作箱に、該当する場合、何を／どの器具に／どれだけ／どの順番で／どのように加えるか／温度／時間／速度／観察事項／次へ進む条件／異常時の対応／操作後の処理を書く。
O7 情報量が多い場合は操作箱の近くに「条件／注意／観察・記録／定義／異常時／廃棄・洗浄」の補足欄を置く。
O8 参照先の文書内完結：「表1のように」「表2に従う」「図1参照」「実験4と同様」「前と同じ方法」を単独で使わない。参照対象を掲載するか内容を完全に展開する。
O9 原典の装置図を使う場合は、図番号・図の名称・出典ファイル名・掲載ページを付す。
O10 化学式：本文とフローチャート内で正式な上下付きを使う（H₂O、Na₂S₂O₃、NH₃、AgNO₃、Cu²⁺、Cl⁻、w₁、w₂、i_t、i_T、E°、Δw）。文字化けを理由に通常数字へ置き換えない。PDF化後に添字の判読・欠落文字・見切れ・枠外はみ出し・矢印との重なりを確認する。
O11 ページ分割：1ページに適切な大きさで収まらない場合は原典の操作番号の境界で複数ページに分割する。無理に縮小しない。操作番号をページ間で連続させ、全ページに実験項目名と「前ページから」「次ページへ続く」を付す。
O12 原典の各操作番号を成果物の各操作へ一対一で対応付ける。
O13 定量条件を省略しない：体積・質量・濃度・温度・時間・滴下速度・測定間隔・電位間隔・電流レンジ・波長・pH・洗浄回数・繰り返し回数・許容差・終了判定値・保存条件・廃液区分。
O14 原典に観察指示がある場合は「観察・記録」欄を設ける。
O15 記録欄を設ける（実験ごとの必須記入項目は別表のとおり）。
O16 安全操作は対応操作の直近に明示する（例：濃硝酸はドラフト内、保護眼鏡・手袋、メタノールの毒性/引火性、Pt電極を王水に浸けない、洗浄後のPt電極を素手で触らない、電解停止後は直ちに電極を液から離す、参照極内部液を入れすぎない、測定中は補充口を開ける、保管時は補充口を塞ぐ、参照極先端を飽和KClに浸す）。
O17 測定後の処理まで操作に含める：電極洗浄、G3洗浄、沈殿回収、装置の初期状態への復帰、参照極の保管、試薬ビンの処理、廃液区分、器具返却。
O18 付録Dに原典操作対応表（原典箇所／原典の操作要点／成果物の該当箇所／省略有無／確認結果）を付す。
O19 電解重量分析では原典の表1（ポテンショスタット/ガルバノスタットの初期状態と機能、①〜⑫）と表2（コネクタのクリップと接続する電極：実験4・5と実験6）を成果物内に収録する。
O20 電解重量分析では装置操作を完全に書く：電源、表示切替、電流レンジ、FUNCTION、P-STAT/G-STAT、EXT.SET、極性、設定ダイアル、操作順序、読取位置、レンジ変更条件、極性変更時のダイアル操作、終了後に戻す初期状態。

■V 検証
V1 付録A 要件充足表：R-ID／判定（満たした・一部・未達・該当なし）／該当箇所／裏付け（原典ページ・操作番号の引用）。1要件1行、一括判定しない。全項目を「満たした」に寄せない。対象外は「該当なし」。
V2 S2の判定：Web補完で必須項目を補えた場合は「満たした」。値が無い/適用できない場合は理由と出典を示せば充足。
V3 付録B 未確認事項一覧（無ければ「なし」）。
V4 付録C 推論箇所一覧（推論と前提条件。無ければ「なし」）。
V5 付録E 原典差分監査表：数値の欠落／条件の欠落／順序変更／器具・試薬・注意・分岐・反復・洗浄廃棄・参照表図の欠落／誤った要約／原典にない追加。
V6 付録F 定義一覧（原典の全定義文）。
V7 番号監査：欠番・重複・逆行・階層飛び・存在しない節への参照・図表番号の重複。
V8 自己完結性試験：原典を開かずに「最初に準備するもの／器具の個数／試薬の濃度と量／操作順／温度と時間／次へ進む条件／不成立時の戻り／記録事項／装置設定／電極接続／終了判定／後処理／計算に必要な値」に答えられること。
V9 優先順位：安全性 > 原典どおりの再現性 > 操作条件の完全性 > 分岐・反復の明確性 > 視認性 > 簡潔さ。
V10 修正指示は明示がなくても新しい受入要件として自動追加し、以後すべて累積適用する。

6. 運用ルール

【運用ルール（エージェントと一緒に使う）】
1. 受入基準Rはエージェントの手順欄に入れず、タスクごとに貼る。手順欄は8,000字上限があり、ナレッジは「事実のグラウンディング用」でシステム指示の代わりにはならないため。
2. 原典PDFと物性一覧PDFは「埋め込みファイル」（.pdf は512MB・20件まで）としてナレッジに入れる。大学配布物の本文を公開Webページへ転載しない。
3. ナレッジは「公開Webサイト 最大4件（それぞれ2階層まで・クエリ不可）＋埋め込みファイル 最大20件」。参照させたい内容は必ず登録したページか埋め込みファイルに入れる。
4. 添字・化学式は「抽出→正規化→組版」の3段で扱う。抽出テキストをそのまま組版しない。
5. 操作用ページは必ずテキスト層を持たせる（画像だけのページを作らない）。検収ではテキスト抽出ではなくページ画像で確認する。
6. 判定には原典の引用を付ける。引用できない「満たした」は無効。対象外の要件は「該当なし」。
7. 1実験=1タスク。10件を一度に作らせない。
8. モデルは検収と作成を「Think deeper」、正規化や整形の下ごしらえは「Quick response」を使い分ける。
9. 版と参照日を必ず書く（原典 Ver.2026／物性一覧／Web出典の改訂日）。
10. 修正指示は口頭でも自動で受入基準に追加し、以後の全成果物に適用する。

8. ナレッジ設定の要点（Microsoft公式ドキュメントで確認済み）

  • 公開Webサイト：最大4件。URLは2階層まで（https://example.org/a/b は可、https://example.org/a/b/c は不可）。クエリ文字列は不可（https://example.org?test=1 は無効）。［出典：Add knowledge sources to your declarative agent / Microsoft Learn］
  • 4件の枠の使い方：必須は ①このハブ（…/repo/）と ②実験手順ページ（…/repo/guide/）の2件。残り2件は予備に残す。
  • 配下ページの自動取り込みは、当該ドキュメントでは明記されていません（未確認）。そのため必ず参照させたい内容は「実際に登録する4つのURLのページ」に載せてください。サイト全体が読まれることを前提にしないでください。
  • 手順欄（Instructions）は8,000字まで。受入基準はここに入れず、タスク本文に貼ります。
  • 埋め込みファイル：最大20件。.docx / .pdf / .pptx / .ppt / .txt は512MBまで、.xls / .xlsx は30MBまで、.html は埋め込み不可。
  • 認証が必要なサイト（SharePoint・社内wiki等）は公開Webサイトとしては使えません。また管理者が「Allow web search in Copilot」を無効化している場合、Webコンテンツはナレッジとして使えません（Knowledge欄のトグル表示にかかわらずポリシーが優先）。
  • Teams／Outlookメールのナレッジは Microsoft 365 Copilot アドオンライセンスが必要です。最小ライセンスで運用するなら、公開Webサイト＋埋め込みファイルだけで構成します。
